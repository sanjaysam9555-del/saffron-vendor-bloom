## Problem

Clicking the Eye icon on the admin project page correctly navigates the URL to `/admin/projects/$id/preview/$clientId`, but the page still shows the admin project view. The preview component never renders.

## Root cause

In TanStack file-based routing, when these two files coexist:

- `src/routes/admin.projects.$id.tsx`
- `src/routes/admin.projects.$id.preview.$clientId.tsx`

The first becomes a **layout** for the second, because they share the `admin.projects.$id` prefix. A layout route must render `<Outlet />` for its children to appear. The admin project file renders its own UI and has no `<Outlet />`, so the preview child route matches but is never displayed.

## Fix

Rename the admin project file so it becomes a leaf index, not a layout:

- `src/routes/admin.projects.$id.tsx` → `src/routes/admin.projects.$id.index.tsx`
- Update the `createFileRoute("/admin/projects/$id")` string inside that file to `createFileRoute("/admin/projects/$id/")` to match the new index path.

After this:
- `/admin/projects/$id` renders the admin project page (index).
- `/admin/projects/$id/preview/$clientId` renders the preview page (sibling), with no shared layout requirement.

No changes needed to the preview route file, the Eye-icon `<Link>`, or any server functions. The auto-generated `src/routeTree.gen.ts` will be regenerated by the Vite plugin.

## Verification

After the rename, navigate from the admin project page using the Eye icon next to a client. The URL should change AND the page content should switch to the "Viewing as client — read-only preview" banner with the vendor grid.
