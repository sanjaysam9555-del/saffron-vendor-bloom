# Horizontal Desktop Timeline (Time › Timeline)

Rebuild the desktop layout of `TimelineRibbon` in `src/components/timeline/VendorTimeline.tsx` so it reads as a true horizontal timeline at a glance. Mobile (vertical alternating ribbon) is unchanged.

## Desktop layout (md and up)

```text
   Jan        Feb        Mar        Apr        May  …  Wedding
───┬──────────┬──────────┬──────────┬──────────┬──────●─────────
   │   ▢      │     ▢    │          │   ▢   ▢  │              
   ▢          │          │     ▢    │          │              
            (cards above OR below the axis, alternating)
```

- One horizontal scroll container (`overflow-x-auto`), full content width derived from earliest item → wedding date.
- A single horizontal axis line across the middle, with **month tick marks + month labels** (e.g. "Jan '26"). Year only shown on Jan or first visible month.
- A wedding-day marker dot + label at the far right on the axis.
- Items positioned absolutely along the axis by their `due_date` (px-per-day scale, e.g. ~6px/day; min 720px wide, capped so it doesn't blow up for far-future dates).
- Cards alternate above/below the axis, each connected to its dot on the axis by a 1px line.
- Unscheduled items: small horizontal strip below the scroll area (current `UnscheduledBand` reused, unchanged).
- Overdue / upcoming / booked variants keep current colors and pills.

## Compact card

Smaller than today's vertical card (~180px wide):
- Category name (one line, truncate)
- **Due date** shown ON the card (replaces the date-on-axis label that exists today)
- Criticality / status pill
- Planned amount (single line)
- No "Actual / Variance / Edit" inline. Admin clicks the card to open the existing `DeadlineEditor` in a popover/expand below the row (same component, just lazy-toggled).

Months go on the axis. Due dates go on the cards. (Currently it's the opposite.)

## Mobile (sm and below)

Unchanged — keeps current vertical spine + full-size cards.

## Implementation notes

- New internal component `HorizontalTimeline` rendered when `md:` matches; existing vertical ribbon kept and shown only on mobile via `md:hidden` / `hidden md:block` wrappers. No shared layout grid logic — clean split avoids regressing mobile.
- Scale helper: `daysFromStart * pxPerDay`, where `start = min(earliest due_date, today)` rounded to month start, `end = weddingDate` rounded to month end. `pxPerDay` chosen so total width ≈ `max(900, monthsSpan * 140)`.
- Month ticks generated by iterating months between start and end.
- Items without `due_date` → unscheduled strip (not on axis).
- Card vertical placement: alternate `top: axis - 110px` / `top: axis + 24px` by index within sorted-by-date order; small collision offset (+8px) if two items are within ~80px horizontally.
- `registerRowRef` still called per category so the existing urgency-strip scroll-to keeps working (uses `scrollIntoView({ inline: "center" })` automatically since it's in a horizontal scroller).

## Files

No schema, server, or data changes.
